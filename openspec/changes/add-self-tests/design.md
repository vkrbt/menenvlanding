## Context

sreda.men — Next.js 16 со статическим экспортом (`output: 'export'`, на выходе `out/`), деплой на Vercel по пушу в `main`. Серверного кода нет, поэтому весь подсчёт возможен только в браузере — это совпадает с требованием анонимности. Стили — один `app/globals.css` с токенами и тёмной/светлой темой, отдельные разделы подключают свой css (пример: `app/book/book.css`). SEO-гейт — `scripts/seo-check.py`. Тест-раннера в проекте нет.

Содержательная база — ресёрч `plans/tests-research/{beck,spielberger-khanin,hads,yakhin-mendelevich}.md`: тексты пунктов, ключи, пороги, контрольные векторы, расхождения рунета. Решения владельца (2026-10-09): Бек — только BDI-IA (Тарабрина 2001); Спилбергер–Ханин — высокая тревожность с 46; HADS — текст Морозовой и соавт. 2023; Яхин–Менделевич — спорные ячейки по изданию 2005 года с пометкой; публикация без лицензий правообладателей.

## Goals / Non-Goals

**Goals:**
- Результат каждого теста совпадает с бумажным бланком по выбранному первоисточнику, и это доказывается автотестами.
- Данные шкал можно сверить с источником глазами: структура данных повторяет структуру ключа в методике.
- Ответы не покидают браузер.
- Новая шкала добавляется файлом данных и тестом, без правок движка.

**Non-Goals:**
- BDI-II, BDI-FS, PHQ-9, GAD-7 и другие шкалы (следующие изменения).
- История результатов, сравнение прохождений, экспорт PDF.
- Серверная часть, аккаунты, отправка результатов специалисту.

## Decisions

### 1. Данные шкал повторяют форму первоисточника, движок нормализует их в таблицу вкладов
Каждая шкала — TS-модуль в `lib/tests/scales/` в той форме, в какой ключ записан в методике: у Спилбергера–Ханина — списки прямых и обратных пунктов, у HADS — явные баллы каждого варианта, у Бека — номер утверждения, у Яхина–Менделевича — таблица коэффициентов по шкалам в сотых долях. Нормализатор превращает всё в единую форму: для каждого пункта и (под)шкалы — массив вкладов по вариантам ответа. Подсчёт — одна чистая функция `score(scale, answers)`: проверка полноты → сумма вкладов по подшкалам → правила-модификаторы (пункт 19 Бека) → категории → флаги риска.

*Почему:* сверка «код ↔ книга» идёт по знакомой форме (список обратных пунктов виден как в методике), а движок остаётся один. *Альтернативы:* (а) отдельная функция подсчёта на шкалу — логика расползается, ловушки повторяются; (б) хранить сразу нормализованные таблицы — сверять с источником тяжелее, ошибка инверсии незаметна.

### 2. Целочисленная арифметика
Все вклады и пороги — целые числа: коэффициенты Яхина–Менделевича в сотых долях, порог ±128. Сравнения с порогами строгие там, где так в источнике («больше +1,28», «меньше −1,28»), включительные — у диапазонных шкал (0–7, 8–10…). Границы записываются в данных явно, с типом включения.

*Почему:* сумма 68 дробных коэффициентов в float даёт ошибки на границе ±1,28.

### 3. Ответ хранится как значение варианта, а не позиция
Ответ — значение варианта (`1..5` у Яхина–Менделевича, номер утверждения у Бека), порядок отображения отделён от значения. Это закрывает ловушку psytests с перевёрнутыми кодами и позволяет показывать варианты в порядке бланка.

### 4. Автотесты на встроенном `node --test`
Скрипт `"test": "node --test --experimental-strip-types lib/tests/"` (Node 22.12 в проекте). Модули `lib/tests/**` не используют алиас `@/` и импортируют друг друга относительными путями с расширением `.ts`, чтобы Node запускал их без сборки. На каждую шкалу — `*.test.ts` с контрольными векторами из ресёрча, границами, обратными пунктами и ловушками.

*Почему:* ноль новых зависимостей. *Альтернатива:* vitest — удобнее, но новая зависимость ради ~5 файлов тестов.

### 5. Маршруты и рендер
`app/tests/page.tsx` — хаб; `app/tests/[slug]/page.tsx` с `generateStaticParams` по реестру шкал. Серверная часть страницы рендерит вводный текст, дисклеймер и методическую справку (индексируемый контент), клиентский компонент `TestRunner` получает сериализуемые данные шкалы пропсами и ведёт прохождение. Стили — `app/tests/tests.css` поверх токенов `globals.css`, по образцу `/book`.

### 6. Состояние прохождения только в памяти
Состояние — `useReducer` в `TestRunner`: индекс вопроса, ответы, экран. Никаких localStorage/sessionStorage/URL-параметров; перезагрузка начинает тест заново. Метрика получает `reachGoal` с целями начала и завершения и идентификатором шкалы в параметрах — без баллов и категорий. Цели нужно завести в интерфейсе Метрики.

*Почему:* анонимность — часть оффера и требование спеки; восстановление прогресса не стоит риска утечки на общем устройстве.

### 7. Экран результата: числа из данных, слова — из редакционного слоя
Категории (границы и официальные названия) живут в данных шкалы. Человеческие пояснения и «что делать дальше» — отдельный редакционный файл на шкалу, чтобы правка текста не трогала проверенные данные. Порядок блоков задаётся тяжестью: флаг риска уровня 2 → блок помощи наверху; клиническая категория → совет обратиться к специалисту перед CTA сообщества.

### 8. Контакты экстренной помощи — данные с датой проверки
`lib/tests/crisis.ts`: страна, служба, номер/ссылка, часы работы, URL официального источника, дата проверки. Страны — по аудитории (Польша, Германия, Грузия, Беларусь, Молдова, Россия) плюс международный каталог линий помощи как запасной вариант. Номера проверяются по официальным источникам на этапе реализации, а не берутся из памяти.

### 9. JSON-LD
Для страниц тестов — `WebPage` с `about`, `author`/`publisher` = организация, `isPartOf` = сайт; для хаба — `CollectionPage` с `ItemList`. `MedicalWebPage` не используем (это скрининг, не медицинская услуга; тематика уже YMYL).

## Risks / Trade-offs

- [Публикация BDI, STAI, HADS без лицензий] → решение владельца, риск принят; в методической справке указываем авторов и адаптации.
- [Ошибка переноса текста пунктов из ресёрча] → построчная сверка каждого пункта с `plans/tests-research/*.md` отдельной задачей; данные без перефразирования.
- [Таблица Яхина–Менделевича опирается на одну линию источников (книги Менделевича)] → пометка в методической справке; три спорные ячейки вынесены в комментарии данных с альтернативными значениями.
- [Порог 45/46 у Спилбергера–Ханина спорный] → выбран 46 (большинство сборников), источник указан на странице; граница покрыта тестом.
- [Правило «несколько утверждений → больший номер» для BDI-IA подтверждено только вторичными источниками] → одиночный выбор с подсказкой; отступление от бланка Тарабриной описано в методической справке.
- [YMYL-тема, неверная интерпретация может навредить] → дисклеймеры, блок помощи по пункту 9, нейтральные формулировки, рекомендация специалиста при клинических категориях.
- [Длинный опросник (68 вопросов) утомляет] → прогресс, автопереход, оценка времени на вводном экране.

## Migration Plan

Только добавление новых страниц: деплой пушем в `main`, откат — revert коммита. Перед пушем: `npm test`, `npx next build`, `python3 scripts/seo-check.py`. После деплоя — проверить `/tests/*` на проде и отправить новые URL на переобход в Вебмастере.
