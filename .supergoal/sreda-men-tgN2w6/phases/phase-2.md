## Why

ТЗ требует проверять каннибализацию до публикации, но 40 статей уже опубликованы без такой проверки, и 18 из них сидят в рубрике «Состояния» — без разведения существующего конфликта новые материалы будут наслаиваться на него.

## Work

- Пройти по всем файлам `content/blog/*.md`. Для каждого извлечь: `slug`, `title`, `H1` (первый `#` или заголовок из фронтматтера), первый абзац, `category`, `date_published`.
- Определить **фактический** целевой запрос статьи — по совокупности title, H1 и первого абзаца. Не назначать произвольно: если из текста запрос не читается, так и записать («не определяется»).
- Посчитать внутренние ссылки: вхождения `](/blog/` в теле. Пометить статьи с числом < 3.
- Проверить наличие обязательных блоков: `<!-- CTA -->`, `## Частые вопросы`, `<!-- NOTE -->`, `## Читать дальше`. Выписать отклонения.
- Для статей о состояниях, зависимостях, панических атаках, депрессии — проверить наличие дисклеймера («не заменяет консультацию специалиста» или эквивалент) и блока экстренной помощи (телефоны доверия). Отсутствие — дефект YMYL.
- Свести всё в `seo/audit-existing.md` — одна строка на статью.
- Отдельным разделом «Конфликты» выписать пары и группы статей с пересекающимися целевыми запросами. Особое внимание к группе «нет сил / ничего не хочется»: `apatiya-u-muzhchin`, `nichego-ne-raduet`, `postoyannaya-ustalost`, `vygoranie-u-muzhchin`, `mozg-ne-otdyhaet`, `ne-mogu-rasslabitsya`, `ustal-ot-samorazvitiya`. Проверить и другие пересечения: `kak-perestat-sryvatsya-na-blizkih` / `kak-perestat-sryvatsya-na-okruzhayushchih` / `kak-perestat-kopit-zlobu`; `muzhskaya-terapevticheskaya-gruppa` / `muzhskaya-gruppa-online` / `gruppa-ili-psiholog`; `odinochestvo-v-emigracii` / `emigrantskaya-depressiya`.
- Для каждого конфликта вынести вердикт: `склеить` / `развести интенты` / `переназначить целевой запрос` / `оставить как есть` — с обоснованием в одну фразу. Вердикты **не применять** — применение в фазе 8, когда будут готовы ядро и архитектура.
- Для проверки, действительно ли два запроса конкурируют, а не обслуживают разные интенты, свериться с выдачей (WebSearch): совпадают ли типы результатов в топе.

## Acceptance criteria (all must pass — verify each in transcript)

- В `seo/audit-existing.md` число строк таблицы равно числу файлов `content/blog/*.md` — подтверждено командой подсчёта; ни один файл не пропущен
- Для каждой статьи выведен фактический целевой запрос, извлечённый из title/H1/первого абзаца, либо явная отметка «не определяется»
- Раздел «Конфликты» содержит каждую пару или группу статей с пересекающимся целевым запросом, у каждой — вердикт одного из четырёх видов и обоснование в одну фразу
- Для каждой статьи посчитано фактическое число внутренних ссылок на `/blog/`; статьи с числом < 3 выписаны отдельным списком
- Проверено наличие блоков `<!-- CTA -->`, `## Частые вопросы`, `## Читать дальше`; отклонения выписаны (или явно указано, что отклонений нет)
- Для статей о состояниях, зависимостях и кризисных темах проверено наличие дисклеймера и блока экстренной помощи; отсутствующие выписаны как дефект YMYL
- Ни один вердикт не применён к файлам: `git status` показывает изменения только в `seo/`, файлы `content/blog/` не тронуты
