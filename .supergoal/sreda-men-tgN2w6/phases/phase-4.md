## Why

Ни одной pillar-страницы не существует, поэтому по определению ТЗ («кластер = pillar + сателлиты») сейчас закрыто ноль кластеров, хотя написано 40 статей; без хабов и правил перелинковки волны контента придётся переподшивать задним числом.

## Work

- Написать `seo/architecture.md`: схема URL-структуры (существующие и планируемые разделы), карта «кластер → pillar → сателлиты» по принятым в фазе 3 кластерам, правила перелинковки, распределение материалов по кластерам и месяцам.
- Сформулировать правила перелинковки проверяемо: минимум внутренних ссылок на материал (≥3), обязательная ссылка на pillar своего кластера, обязательная ссылка на BOFU-материал из каждого TOFU-материала кластера, естественные анкоры по интенту, запрет на сквозные подвальные простыни ссылок.
- Реализовать в коде страницы рубрик: маршрут `app/blog/[category]/page.tsx` (или эквивалент, не конфликтующий с `app/blog/[slug]/page.tsx` — проверить коллизию маршрутов и при необходимости вынести рубрики в `app/blog/tema/[category]/`). Каждая рубрика — список статей своего кластера.
- Дать рубричным страницам уникальные `title`, `description`, `canonical`, ровно один `H1`, вводный текст с целевым запросом рубрики.
- Добавить рубрики в `app/sitemap.ts`.
- Добавить `BreadcrumbList` в JSON-LD статьи и рубрики (`lib/jsonld.ts`).
- Добавить ссылки на рубрики в навигацию блога (`app/blog/page.tsx`).
- Не трогать `lib/markdown.ts` без крайней нужды: это ручной порт парсера, любая правка ломает паритет 40 страниц.
- Это единственная фаза, где проверяется паритет вёрстки — здесь правки затрагивают рендер. Подготовить эталон один раз: `git worktree add /tmp/sreda-old c596a89`, затем `npm run verify -- --old=/tmp/sreda-old`. Без `--old` скрипт выходит с кодом 2 и ничего не проверяет. После фазы worktree можно удалить (`git worktree remove /tmp/sreda-old`).

## Acceptance criteria (all must pass — verify each in transcript)

- `seo/architecture.md` содержит схему URL-структуры со всеми существующими и планируемыми разделами
- Для каждого принятого в фазе 3 кластера указан URL pillar-страницы и перечень сателлитов — существующих и планируемых
- Правила перелинковки содержат не менее 4 пунктов, и каждый выражен числом или явным адресатом ссылки (например «≥3 внутренние ссылки», «ссылка на pillar своего кластера обязательна», «каждый TOFU-материал кластера ссылается на BOFU-материал кластера»); пунктов с оценочными формулировками ноль
- `npm run build` собирает страницу для каждой рубрики; страницы присутствуют в `out/` — подтверждено листингом
- Каждая рубричная страница имеет уникальные `title`, `description`, `canonical` и ровно один `H1` — проверено на собранном HTML, вывод по минимум трём рубрикам
- Рубричные страницы присутствуют в `out/sitemap.xml` — подтверждено grep'ом
- `BreadcrumbList` присутствует в JSON-LD статьи и рубрики — фрагмент из собранного HTML в транскрипте
- `npm run verify -- --old=/tmp/sreda-old` завершается кодом 0 при подготовленном worktree: паритет вёрстки существующих 40 статей не нарушен. Если паритет расходится осознанно (например добавлены хлебные крошки в шапку статьи) — расхождение перечислено и записано в `seo/decisions.md` как принятое, а не замолчано
- Навигация не сломана: `/blog` отдаёт список всех статей, ссылка «Блог» в шапке ведёт на `/blog` — проверено на собранном HTML

## Notes

Коллизия маршрутов `[slug]` и `[category]` на одном уровне в App Router — реальный риск. Проверь до реализации; если конфликт — вынеси рубрики на отдельный сегмент и отрази это в `seo/architecture.md`.

Паритет — главный страж этой фазы, и запускать его надо только с `--old=/tmp/sreda-old`: без каталога эталона скрипт выходит с кодом 2, ничего не проверив, и это легко принять за успех. Если паритет краснеет, значит правка задела рендер существующих статей — это не «мелкая регрессия», а нарушение контракта 40 проиндексированных страниц. Осознанные расхождения (например добавленные хлебные крошки) допустимы, но перечисляются и записываются в `seo/decisions.md`.

Pillar-страницы здесь только проектируются. Пишутся они в фазах 9–11.
