## Why

ТЗ требует отчёт, по которому видно работающие и неработающие кластеры и приняты решения по отстающим; без заранее заданной структуры, порогов и процедуры замера отчёт выродится в пересказ процесса.

## Work

- Достроить `seo/measurement.md`: метрики, источники, контрольные периоды, процедура замера, шаблон сводки, журнал замеров, правила решений по отстающим кластерам.
- Определить ≥6 метрик, у каждой — точный источник и способ получения. Как минимум: доля проиндексированных материалов (раздельно Яндекс/Google), показы по кластерам, клики по кластерам, средняя позиция по целевым запросам, переходы из блога на `/vstrecha`, клики по CTA (цель Метрики), заявки (со слов владельца — с пометкой об источнике).
- Задать контрольный период конкретной длительностью и указать дату первой контрольной точки.
- Задать порог «кластер работает / не работает» в числах, а не словами.
- Задать правило решения по отстающему кластеру: что делается при недоборе (дописать под реальные запросы из Search Console / переназначить целевой запрос / закрыть кластер) и при каких цифрах что именно.
- Перевести пороги эскалации из ТЗ в числа: «не индексируется дольше трёх недель» и «конверсия страницы встречи ниже ожидаемого диапазона два контрольных периода подряд» — с указанием ожидаемого диапазона и обоснованием, откуда он взят (базовая ставка для молодого домена в узкой нише; помечено как гипотеза, уточняется по первым данным).
- Написать `scripts/seo-report.py`: читает выгрузки из `seo/data/`, сводит в таблицу «кластер → показы → клики → средняя позиция → переходы на /vstrecha», привязывая URL к кластерам через `seo/core.md`. При отсутствии выгрузок печатает явное сообщение и завершается кодом 0.
- Создать `seo/data/README.md`: в каком формате класть выгрузки Вебмастера, Search Console и Метрики, как называть файлы.
- Шаблон сводки — по требованию ТЗ «без пересказа процесса»: разделы «что сделано», «что измерено», «что из этого следует», «что меняется в плане».
- Индексацию вести раздельно по Яндексу и Google — в шаблоне обе колонки.
- Напечатать блок эскалации: какие выгрузки нужны от владельца и с какой периодичностью.

## Acceptance criteria (all must pass — verify each in transcript)

- `seo/measurement.md` определяет ≥6 метрик, у каждой указан точный источник данных и способ получения
- Контрольный период задан конкретной длительностью; указана дата первой контрольной точки
- Порог «кластер работает / не работает» задан в числах
- Правило решения по отстающему кластеру задано: какое действие при каких цифрах — без оценочных формулировок
- Пороги эскалации из ТЗ переведены в числа, ожидаемый диапазон конверсии указан и помечен как гипотеза с обоснованием
- `scripts/seo-report.py` запускается на пустой `seo/data/`, печатает явное сообщение об отсутствии данных и завершается кодом 0
- `scripts/seo-report.py` запускается на тестовом CSV и печатает таблицу с привязкой URL к кластерам — вывод в транскрипте
- Шаблон сводки содержит ровно четыре раздела: что сделано, что измерено, что из этого следует, что меняется в плане
- Шаблон индексации содержит отдельные колонки для Яндекса и Google

## Notes

Скрипт не должен изображать работу при отсутствии данных. Пустой вывод с честным сообщением — правильное поведение; выдуманные цифры — прямое нарушение ТЗ.

Ожидаемый диапазон конверсии страницы встречи неоткуда взять фактически: сайту 4 месяца, страницы не было. Ставь его как гипотезу с обоснованием и явным условием пересмотра по первым реальным данным. Не выдавай за норму отрасли.

Тестовый CSV для проверки скрипта — синтетический, он живёт в тестовой директории и не попадает в `seo/data/`, чтобы не смешаться с реальными выгрузками.
