# Roadmap: органический рост sreda.men

**Task:** Вывести sreda.men в органическую выдачу Яндекса и Google по запросам русскоязычных мужчин и обеспечить поток заявок на встречи силами контента, без бюджета.
**Type:** brownfield, content/SEO, ui (частично — страница встречи и рубрики блога)
**Created:** 2026-07-29
**Total phases:** 12

## Context summary

- **Stack:** Next.js 15 (App Router, `output: 'export'`), React 19, TypeScript. Контент — Markdown в `content/blog/*.md` со своим диалектом разметки (`lib/markdown.ts`). Деплой Vercel.
- **Package manager:** npm
- **Build / test / lint commands:** `npm run build` · `python3 scripts/seo-check.py` (сквозной гейт, пишется в фазе 1) · `python3 seo/neurocheck.py <файл>` (гейт человечности, порог ≥80% по строке `HUMAN(+likely) / Сегментов`) · `npm run verify -- --old=<worktree>` (паритет вёрстки, только фаза 4)
- **Risky areas:** `lib/markdown.ts` — ручной порт парсера, любая правка ломает побайтовый паритет 40 страниц; `app/sitemap.ts` — источник истины карты сайта; фронтматтер статей парсится плоско, без YAML (двоеточие в значении ломает поле).

## Границы прогона (важно)

Цель ТЗ — 12-месячная программа (25+ кластеров, ориентир 240 материалов). Один автономный прогон её не закрывает физически: индексация и накопление показов занимают недели календарного времени, а не действий агента.

**Этот прогон закрывает веху 1:** рабочая система (ядро, архитектура, воронка, измерение, план программы) + ретро-приведение 40 существующих статей в порядок + закрытие первых трёх кластеров целиком. Дальнейшие волны идут следующими прогонами по `seo/state.md`.

Критерии ТЗ распределены так:

| Критерий ТЗ | Где закрывается |
|---|---|
| 1. ≥25 кластеров, pillar + сателлиты | Инвентаризация и план — фаза 3 и 7 (честный ответ, сколько кластеров реально есть). Закрытие первых трёх — фазы 9–11. Остальные — последующие прогоны по `seo/content-plan.md` |
| 2. ≥60% материалов проиндексированы с показами | Фаза 1 (диагностика, устранение технических причин) + фаза 6 (процедура замера). Сам факт достижения — вопрос календаря, отслеживается на контрольных точках |
| 3. Материалы → страница встречи → измеренная конверсия | Фаза 5 (страница встречи + цели Метрики) + фаза 6 (методика замера). Первые цифры — на контрольной точке после публикации волн |
| 4. Measurement-отчёт с решениями по отстающим | Фаза 6 (каркас) + фаза 12 (первая сводка и первые решения) |

## Assumptions

Решения приняты, чтобы не гонять круги. Если что-то неверно — останови прогон и скажи:

- **A1.** Владелец имеет доступ к Яндекс.Вебмастеру и Метрике и предоставляет выгрузки по запросу на контрольных точках. Автосбор через API не настраивается — токенов нет.
- **A2.** Google Search Console либо уже подтверждён, либо владелец подтвердит его по инструкции из фазы 1.
- **A3.** Заявка = переход по `forms.gle/tvTnJuyBoedpJZ989`. Фактические отправки формы недоступны; конверсия измеряется до клика, глубже — со слов владельца. Это ограничение метода, оно фиксируется в отчёте.
- **A4.** Прогон закрывает веху 1; полные 25 кластеров — горизонт программы в `seo/content-plan.md`.
- **A5.** 22 черновика `drafts/writing/` идут отдельной рубрикой «Исследования», без натягивания на коммерческие ключи.
- **A6.** Шаблон статьи не меняется: проза → `<!-- CTA -->` → `## Частые вопросы` → `<!-- NOTE -->` → `## Читать дальше`.
- **A7.** Артефакты ТЗ (`plan.md`, `state.md`, `core.md`, `architecture.md`, `content-plan.md`, `funnel.md`, `measurement.md`, `decisions.md`) кладутся в `seo/`, рядом с существующими `01-search-intents.md`…`03-seo-strategy.md`, а не в корень репозитория. Имена файлов — как в ТЗ.
- **A8.** Частотность проверяет владелец пачками в Wordstat. Прогон на этом не останавливается: приоритеты строятся на гипотезах с явной пометкой и пересобираются, когда цифры придут.
- **A9.** Продукт везде называется «сообщество»/«клуб». «Мужская группа поддержки» — только поисковый ключ внутри текста.

## Risk top 3

1. **Google не откроется за горизонт прогона** — вероятность высокая. Домену 4 месяца, ссылочный профиль близок к нулю, ниша YMYL-смежная. Митигация: критерий индексации ведётся раздельно по Яндексу и Google; по Google фиксируется честная причина (возраст + ссылочное, не техника) и запускается линия нативного ссылочного разгона (подкаст, YouTube-описания, диаспорные медиа) без бюджета.
2. **Погоня за 25 кластерами уронит качество** — вероятность средняя. Митигация: фаза 3 даёт честную инвентаризацию; кластер принимается только если проходит тест «pillar + минимум 4 сателлита с различающимся интентом»; не прошедшие — письменный отказ в `seo/decisions.md`, а не растягивание.
3. **Конверсия окажется неизмеримой** — вероятность средняя. Заявка уходит в Google Forms, вне периметра Метрики; страницы встречи не существует. Митигация: фаза 5 создаёт страницу встречи как отдельный измеримый URL и ставит цель Метрики на клик по CTA; обрыв атрибуции за формой фиксируется как ограничение метода.

## Phase 1 — Диагностика индексации

**Why:** В Google 0 проиндексированных страниц против рабочей индексации в Яндексе; без объяснения причины критерий 2 недостижим на половине целевого рынка, а любые контентные усилия под Google — стрельба вслепую.

**Deliverables:**
- `seo/measurement.md` — раздел «Индексация»: результаты живых проверок, вердикт о причине, разделение Яндекс/Google
- `seo/decisions.md` — решение по линии Google с обоснованием
- Устранённые технические причины в коде (если найдутся) — правки в `app/`, `lib/` или конфигах
- `seo/checklist-webmaster.md` — пошаговая инструкция владельцу: что подтвердить и отправить в GSC, Вебмастере, Bing
- `scripts/seo-check.py` — сквозной гейт качества для всех последующих фаз (уникальность title/description, один H1, canonical, сверка sitemap с файлами, целостность внутренних ссылок, дубли целевых запросов)

**Acceptance criteria:**
- [ ] Для каждой из 43 записей sitemap выполнена живая проверка: HTTP-статус, наличие `X-Robots-Tag`, наличие `<meta name="robots">`, совпадение canonical с запрошенным URL. Результат — таблица в `seo/measurement.md` со 43 строками
- [ ] Проверено и зафиксировано: sitemap отдаёт `200` и валидный XML; robots.txt не запрещает `/blog/`; ни одна статья не отдаёт `noindex`
- [ ] Проверено расхождение между `<loc>` в sitemap и canonical на странице — отдельная строка вердикта (сейчас главная в sitemap значится как `https://sreda.men` без слеша)
- [ ] Записан явный вердикт о причине нулевой индексации в Google одной из формулировок: «техническая, устранена правкой X» / «техническая, требует действия владельца Y» / «нетехническая: возраст домена + ссылочный профиль» — с перечислением проверок, на которых вердикт основан
- [ ] `seo/checklist-webmaster.md` содержит пронумерованные шаги для Google Search Console, Яндекс.Вебмастера и Bing Webmaster Tools, включая точный URL sitemap
- [ ] Если найдены технические дефекты — они исправлены, `npm run build` зелёный, правка описана в `seo/decisions.md`
- [ ] `scripts/seo-check.py` написан и реализует шесть проверок; на копии с искусственно внесённым дефектом завершается ненулевым кодом и называет дефект
- [ ] `python3 scripts/seo-check.py` на текущем репозитории зелёный либо перечисляет реальные дефекты, каждый из которых исправлен или принят записью в `seo/decisions.md`
- [ ] Напечатан явный блок эскалации со списком того, что может сделать только владелец

**Mandatory commands:**
- `npm run build`
- `python3 scripts/seo-check.py`

**Evidence required:**
- Полная таблица проверки 43 URL с колонками: URL, статус, X-Robots-Tag, meta robots, canonical, вердикт
- Вывод `curl -sI` для главной, `/blog`, одной статьи
- Текст вердикта о причине с перечнем опровергнутых гипотез
- Содержимое `seo/checklist-webmaster.md`
- Блок `ЭСКАЛАЦИЯ:` со списком действий владельца

**Dependencies:** none

## Phase 2 — Аудит 40 статей и каннибализации

**Why:** ТЗ требует проверять каннибализацию до публикации, но 40 статей уже опубликованы без такой проверки и 18 из них сидят в одной рубрике — без разведения существующего конфликта новые материалы будут наслаиваться на него.

**Deliverables:**
- `seo/audit-existing.md` — таблица по всем 40 статьям: slug, фактический целевой запрос, кластер, число внутренних ссылок, наличие FAQ/CTA/дисклеймера, конфликтующие статьи, вердикт
- Список пар-конфликтов с обоснованием, почему это каннибализация, а не разные интенты

**Acceptance criteria:**
- [ ] В `seo/audit-existing.md` ровно 40 строк — по одной на каждый файл `content/blog/*.md`, ни одна не пропущена
- [ ] Для каждой статьи выведен фактический целевой запрос: из `title`, `H1` и первого абзаца, а не назначен произвольно
- [ ] Каждая пара статей с пересекающимся целевым запросом выписана в отдельный раздел «Конфликты» с вердиктом одного из четырёх видов: `склеить` / `развести интенты` / `переназначить целевой запрос` / `оставить как есть` — с обоснованием в одну фразу
- [ ] Для каждой статьи посчитано фактическое число внутренних ссылок на `/blog/` и помечены те, у кого меньше 3
- [ ] Проверено наличие обязательных блоков: `<!-- CTA -->`, `## Частые вопросы`, `## Читать дальше` — отклонения выписаны
- [ ] Для статей о состояниях (депрессия, тревога, зависимости, панические атаки) проверено наличие дисклеймера и блока экстренной помощи; отсутствующие выписаны как дефект YMYL
- [ ] Вердикты в аудите не применяются — только фиксируются (применение в фазе 8), чтобы правки шли уже с готовым ядром и архитектурой

- `npm run build`

**Evidence required:**
- Первые 10 строк таблицы аудита в транскрипте + подтверждение количества строк командой подсчёта
- Полный раздел «Конфликты» с вердиктами
- Список статей с числом внутренних ссылок < 3

## Phase 3 — Семантическое ядро

**Why:** ТЗ требует «семантика первична: один запрос — один материал», а сейчас ядра как рабочего документа нет — есть карта интентов, но без привязки к уже занятым запросам и без честного ответа, сколько кластеров реально существует.

**Deliverables:**
- `seo/core.md` — семантическое ядро: кластеры, запросы внутри кластеров, тип интента, стадия воронки, статус покрытия, пометка «гипотеза» на каждой непроверенной оценке частотности
- `seo/core-wordstat-batch-1.tsv`, `-2.tsv`, … — батчи запросов для проверки владельцем, по ≤50 запросов в батче
- Раздел «Инвентаризация кластеров» с честным ответом на вопрос «сколько кластеров реально набирается»
- Раздел «Отклонённые кластеры» + соответствующие записи в `seo/decisions.md`

**Acceptance criteria:**
- [ ] Каждый кластер в `seo/core.md` имеет: название, целевой запрос pillar-страницы, ≥4 запроса под сателлиты, тип интента, стадию воронки, отметку «занят статьёй X» или «свободен»
- [ ] Каждый кластер прошёл тест приёмки: pillar-запрос + ≥4 запроса под сателлиты, различающиеся интентом (разный поисковый вопрос, не переформулировка), причём различие расписано одной строкой на сателлит — прошедшие помечены `ПРИНЯТ`, не прошедшие `ОТКЛОНЁН` с причиной
- [ ] Ни один запрос не назначен двум материалам: проверка на дубли выполнена командой, вывод в транскрипте
- [ ] Каждая статья из аудита фазы 2 привязана ровно к одному кластеру и одному целевому запросу; статьи без кластера выписаны отдельно
- [ ] Кластеры, где выдачу держат агрегаторы и психологические маркетплейсы, проверены через выдачу (не по памяти) и отклонены записью в `seo/decisions.md` с указанием, кто именно держит топ
- [ ] Каждая цифра частотности в `seo/core.md` помечена либо `[гипотеза]`, либо `[Wordstat, <дата>]`. Материалов без пометки нет — проверено grep'ом
- [ ] Батчи Wordstat выгружены в TSV с колонками `запрос`, `регион`, `частотность`, `дата` — последние две пустые под заполнение
- [ ] Напечатан итог инвентаризации в форме: «Принято кластеров: N. Отклонено: M. До целевых 25 не хватает K — источники добора: …» либо «25 кластеров честно не набирается, максимум N, обоснование: …»

**Mandatory commands:**
- `npm run build`

**Evidence required:**
- Итоговая таблица кластеров: название, статус (ПРИНЯТ/ОТКЛОНЁН), число запросов, покрытие существующими статьями
- Вывод команды проверки дублей целевых запросов
- Вывод grep, подтверждающий, что все частотности помечены
- Явный блок инвентаризации с числами
- Список отклонённых кластеров с указанием держателей топа

## Phase 4 — Архитектура и перелинковка

**Why:** Ни одной pillar-страницы не существует, поэтому по определению ТЗ сейчас закрыто ноль кластеров, хотя написано 40 статей; без хабов и правил перелинковки волны контента придётся переподшивать задним числом.

- Хлебные крошки (`BreadcrumbList` в JSON-LD) на статьях и рубриках
- Блок «Читать дальше» приводится к правилу: ссылки на pillar своего кластера + 2–4 статьи кластера

**Acceptance criteria:**

- [ ] Правила перелинковки содержат не менее 4 пунктов, каждый выражен числом или явным адресатом ссылки; пунктов с оценочными формулировками ноль

- [ ] Каждая рубричная страница имеет уникальные `title`, `description`, `canonical` и `H1` — проверено на собранном HTML

## Phase 5 — Воронка и страница встречи

**Why:** Целевое действие — заявка, но между статьёй и формой нет страницы, снимающей главный барьер аудитории («страх группы»), и именно конверсию этой страницы ТЗ требует измерить — а её не существует.
