# Доступы к панелям через MCP

Как дать мне прямой доступ к Вордстату, Вебмастеру и Метрике, чтобы часть эскалаций из [state.md](state.md) закрывалась без ручных выгрузок.

Пакеты — из [altrr2/yandex-tools-mcp](https://github.com/altrr2/yandex-tools-mcp), опубликованы в npm: `yandex-wordstat-mcp` 2.0.1, `yandex-webmaster-mcp` 1.2.1, `yandex-metrika-mcp` 1.2.1.

---

## Правило про токены

**Токены не присылать мне в переписку.** Всё, что попадает в диалог, уходит в модельный контур и остаётся в логе сессии. Команды `claude mcp add` выполняются в терминале — я вижу только имя переменной, не значение.

По той же причине я не читаю `~/.zshrc`, не выполняю `env` и не печатаю значения переменных. Проверить, что доступ появился, могу фактом наличия и вызовом самого инструмента.

---

## 1. Метрика — бесплатно, OAuth

Закрывает: проверку целей, отчёты по конверсиям, страницы входа. Это заменяет ручную выгрузку `metrika-YYYY-MM-DD.csv`.

1. [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) → платформа **Веб-сервисы**, Redirect URI `https://oauth.yandex.ru/verification_code`
2. В доступах включить **Яндекс Метрика**, право `metrika:read`
3. Получить токен: открыть в браузере `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>` и скопировать со страницы
4. В терминале:

```bash
claude mcp add yandex-metrika \
  -e YANDEX_METRIKA_TOKEN=<токен> \
  -- npx -y yandex-metrika-mcp
```

**Чего это НЕ решает.** Сервер работает только на чтение: `get-goals` показывает список целей, но создать их нельзя. Четыре цели `cta_click`, `cta_vstrecha`, `cta_article`, `cta_landing` на счётчике 111109205 всё равно заводятся руками в интерфейсе. Зато после этого я смогу проверить, что они заведены правильно, и дальше собирать сводку сама.

---

## 2. Вебмастер — бесплатно, OAuth

Закрывает: показы, клики, позиции, статус индексации. Заменяет `webmaster-*.csv` и отвечает на открытый вопрос из диагностики A1 — какие страницы не в индексе и почему.

1. Там же, [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new), можно тем же приложением
2. Права: `webmaster:hostinfo` (статистика сайта) и `webmaster:verify` (подтверждение прав)
3. Токен — тем же способом, что выше
4. В терминале:

```bash
claude mcp add yandex-webmaster \
  -e YANDEX_WEBMASTER_TOKEN=<токен> \
  -- npx -y yandex-webmaster-mcp
```

Токен живёт полгода, потом повторить шаг 3.

---

## 3. Вордстат — платный, требует Yandex Cloud

Закрывает эскалацию №4: проверку частотности всех 119 запросов ядра.

Работает не через привычный wordstat.yandex.ru, а через Wordstat v2 в составе Yandex Cloud Search API.

1. [console.yandex.cloud](https://console.yandex.cloud/) → создать **сервисный аккаунт**, роль `search-api.webSearch.user`
2. Создать для него **API-ключ** со скоупом `yc.search-api.execute`
3. Скопировать **ID каталога** (вида `b1g…`)
4. В терминале:

```bash
claude mcp add yandex-wordstat \
  -e YANDEX_SEARCH_API_KEY=<ключ> \
  -e YANDEX_FOLDER_ID=<folder id> \
  -- npx -y yandex-wordstat-mcp
```

### Про деньги

ТЗ запрещает тратить бюджет, поэтому цифры привожу явно — решение за владельцем.

По [тарифам Search API](https://aistudio.yandex.ru/docs/ru/search-api/pricing), блок Wordstat, колонка «Цена за 1000 запросов, вкл. НДС»:

| Метод | Цена за 1000 | Что даёт |
|---|---|---|
| `GetTop` | 20 ₽ | популярные запросы по фразе за 30 дней |
| `GetDynamics` | 20 ₽ | динамика по месяцам/неделям/дням |
| `GetRegionsDistribution` | 50 ₽ | распределение по регионам |
| `GetRegionsTree` | не тарифицируется | коды регионов |

На 119 запросов ядра: около **2,4 ₽** по `GetTop`. С разбивкой по регионам — ещё около 6 ₽. То есть полная проверка ядра стоит меньше десяти рублей.

Настоящее препятствие не сумма, а то, что Yandex Cloud требует платёжный аккаунт с привязанной картой. Наличие стартового гранта для новых аккаунтов я по документации подтвердить не смогла — не проверяла, поэтому и не утверждаю.

## Порядок, который я бы предложила

Метрика и Вебмастер — бесплатны и закрывают две из четырёх эскалаций плюс открытый вопрос по индексации. Их стоит подключить в любом случае.

Вордстат — отдельное решение про платёжный аккаунт. Пока его нет, батчи `core-wordstat-batch-*.tsv` заполняются руками, а сверка идёт через `python3 seo/wordstat_ingest.py`. Производство контента ни то ни другое не блокирует.

---

## Две грабли, на которые я уже наступила

**Вордстат нельзя авторизовать тем же OAuth-приложением.** Метрика и Вебмастер ходят по OAuth-токену с oauth.yandex.ru. Вордстат v2 — это Yandex Cloud Search API, у него другая система доступа: сервисный аккаунт, роль и API-ключ в консоли облака. Права в OAuth-приложении на него не распространяются, и сервер в `claude mcp list` просто не появится.

**Новые серверы не видны уже запущенной сессии.** Claude Code читает список MCP при старте. После `claude mcp add` сервер отвечает на `claude mcp list`, но инструменты в текущем диалоге не появятся — нужен перезапуск.
