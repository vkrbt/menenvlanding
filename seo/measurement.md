### 1.3. Прочие технические проверки

| Что проверено | Как | Результат |
|---|---|---|
| `robots.txt` не закрывает блог | Разбор всех `Disallow` | Запреты только на `/og-image`, `/og-book`, `/instagram-carousel`, `/muzhskaya_sreda_books`. `/blog/` открыт |
| `sitemap.xml` валиден и доступен | HTTP + разбор XML | `200`, XML разбирается, 43 `<loc>` |
| Карта сайта не разъехалась с контентом | Сверка в обе стороны: 40 файлов `content/blog/*.md` ↔ 40 blog-URL в карте | Расхождений нет |
| Подтверждение домена в панелях | Метатеги на живой главной | `google-site-verification` и `yandex-verification` присутствуют (заданы в `app/page.tsx`) — значит домен в обеих панелях подтверждался |
| Клоакинг / разный ответ ботам | Запрос статьи с UA Googlebot и обычным UA | Ответы побайтово идентичны (83 042 байта), статус `200`. YandexBot — тоже `200` |
| Контент доступен без исполнения JS | Разбор сырого HTML, отданного Googlebot | 12 233 символа текста статьи и `H1` присутствуют в исходном HTML. Сайт — статический экспорт, клиентский рендеринг для индексации не требуется |
| JSON-LD валиден | Разбор всех блоков `application/ld+json` | Главная: `Organization`, `WebSite`, `Service`, `FAQPage`. `/blog`: `CollectionPage`. Статья: `Article`, `BreadcrumbList`, `FAQPage`. Все блоки — валидный JSON |
| Возраст домена | `whois` | Дата создания `2026-03-24` — домену ~4 месяца |

### 1.4. Вердикт о причине нулевой индексации в Google

**Нетехническая: возраст домена и ссылочный профиль.**

Опровергнутые гипотезы — каждая закрыта конкретной проверкой:

| Гипотеза | Чем опровергнута |
|---|---|
| Блокировка в `robots.txt` | Разбор `Disallow`: `/blog/` не задет |
| `noindex` в заголовке или метатеге | 43/43 URL без `X-Robots-Tag` и без `<meta name="robots">` |
| Битые статусы или редиректные цепочки | 43/43 отдают `200`, хопов 0 |
| Карта сайта недоступна или невалидна | `200`, валидный XML, 43 URL |
| Карта сайта разошлась с контентом | Сверка в обе стороны, расхождений 0 |
| Неверные canonical, склеивающие страницы | На всех 43 canonical равен собственному URL |
| Домен не подтверждён в Search Console | Верификационный метатег Google присутствует на живой главной |
| Googlebot получает другой ответ | Побайтово идентичный HTML, статус `200` |
| Контент рендерится только на клиенте | Текст статьи и `H1` есть в сыром HTML |
| Невалидная разметка, ломающая разбор | Все блоки JSON-LD — валидный JSON |

Технических причин не осталось. Остаются: возраст домена 4 месяца, ссылочный профиль близок к нулю, тематика YMYL-смежная — сочетание, при котором Google обходит и индексирует молодой сайт заметно медленнее Яндекса. Наблюдаемая картина ровно такая: Яндекс проиндексировал, Google — нет.

**Чего я проверить не могу и что уходит в эскалацию:** отправлена ли карта сайта в Search Console и что показывает отчёт «Страницы» — «Просканировано, но пока не проиндексировано» / «Обнаружено, не просканировано» / «Исключено». Это единственное, что отделяет вердикт от полной определённости. Инструкция — в [checklist-webmaster.md](checklist-webmaster.md).

### 1.5. Замечание, не влияющее на вердикт

В карте сайта главная указана как `https://sreda.men` без завершающего слеша, и `canonical` на ней такой же. Обе системы нормализуют пустой путь к `/`, редиректа нет (0 хопов), расхождения между картой и canonical нет. Правки не требует; зафиксировано, чтобы не всплывало повторно.

### 1.6. Как эта метрика ведётся дальше

Индексация отслеживается раздельно по Яндексу и Google — сводить их в одну цифру бессмысленно, поведение систем на молодом домене расходится принципиально. Пороги, контрольные периоды и процедура замера задаются в фазе 6.

## 2. Метрики

Каждая метрика — с точным источником и способом получения. Автоматического сбора нет: токенов к API панелей нет, данные приходят выгрузками от владельца в `seo/data/`, оттуда их разбирает `scripts/seo-report.py`.

| # | Метрика | Источник | Как получить | Разрез |
|---|---|---|---|---|
| М1 | Доля проиндексированных материалов, **Яндекс** | Яндекс.Вебмастер → Индексирование → Страницы в поиске | Выгрузка списка, сверка с `content/clusters.json` | по кластерам |
| М2 | Доля проиндексированных материалов, **Google** | Search Console → Индексирование → Страницы | Числа из отчёта + список причин непроиндексированности | по кластерам |
| М3 | Показы по кластерам | Вебмастер → Поисковые запросы; Search Console → Результаты поиска | Выгрузка по URL, агрегация скриптом | по кластерам, раздельно по системам |
| М4 | Клики и CTR по кластерам | там же | там же | по кластерам |
| М5 | Средняя позиция по целевым запросам | там же | Сверка с `seo/core.md` — запрос к кластеру привязан | по запросам |
| М6 | Переходы из блога на `/vstrecha` | Метрика → Содержание → Страницы входа + отчёт по переходам | Выгрузка визитов | по страницам-источникам |
| М7 | **Конверсия `/vstrecha` в клик по CTA** | Метрика, цель `cta_vstrecha` / визиты на `/vstrecha` | Выгрузка достижений целей | общая |
| М8 | Конверсия статей в клик по CTA | Метрика, цель `cta_article` в разрезе параметра `page` | там же | по статьям и кластерам |
| М9 | Заявки фактические | Google Forms, у владельца | Со слов владельца | общая, помечается как непроверяемая мной |

**М9 стоит особняком.** Форма живёт на домене Google, счётчика там нет. Цифра может попадать в отчёт, но всегда с пометкой «со слов владельца» — я её не измеряю и подтвердить не могу. Подробнее — [funnel.md](funnel.md), раздел 6.

**Индексация ведётся раздельно по системам.** Сводить М1 и М2 в одну цифру нельзя: на момент старта в Яндексе страницы в индексе, в Google — ноль. Усреднение спрячет ровно ту разницу, ради которой метрика заводится (решение Р-001).

## 4. Пороги: работает кластер или нет

Оцениваются только кластеры, у которых прошло **не менее 8 недель** с публикации последнего материала. Раньше судить нельзя — это будет оценка скорости индексации, а не качества кластера.

| Состояние | Условие (Яндекс, за контрольный период) | Что это значит |
|---|---|---|
| **Работает** | ≥100 показов И ≥5 кликов И ≥60% материалов кластера имеют хотя бы 1 показ | Кластер живой, наращивать |
| **Разгоняется** | ≥20 показов, но не дотягивает до «работает» | Рано судить, ждать следующий период |
| **Не работает** | <20 показов ИЛИ <30% материалов кластера имеют показы, при возрасте ≥8 недель | Требует решения по таблице ниже |
| **Слепая зона** | 0 показов при том, что материалы в индексе | Проблема не в кластере, а в спросе или в целевых запросах |

Для Google пороги на первый год не задаются: при нулевой базе любой порог будет выдуманным. Отслеживается факт — появились страницы в индексе или нет.

**Конверсия `/vstrecha` — ожидаемый диапазон `[гипотеза]`: 3–8% визитов в клик по CTA.**

Откуда цифра: нижняя граница — типичная конверсия информационной страницы в целевое действие при холодном трафике; верхняя — с поправкой на то, что на `/vstrecha` попадают уже прогретые люди, пришедшие по внутренней ссылке из статьи. Проверенных данных по нише нет, собственных данных нет — сайту 4 месяца, страницы до сегодня не существовало. **Это гипотеза, а не норма отрасли, и она пересматривается по первым же реальным данным КТ-3.**

## 5. Правила решений по отстающим

Применяются к кластеру в состоянии «не работает» или «слепая зона».

| Что видим | Решение | Почему |
|---|---|---|
| Показы есть, кликов почти нет (CTR <1% при позиции ≤20) | Переписать `title` и `description` под запрос | Страница видна, но не выбирается — проблема сниппета, не контента |
| Показы есть, позиция >30 стабильно два периода | Дописать материал под реальные запросы из Вебмастера | Релевантности не хватает, а реальный спрос уже виден в отчёте |
| Показы по запросам, которых нет в ядре | Добавить запросы в `core.md`, дописать разделы | Самый дешёвый рост: спрос уже подтверждён |
| Показов почти нет, но материалы в индексе | Проверить целевой запрос на каннибализацию, затем — на реальность спроса | Либо запрос занят своей же страницей, либо его никто не ищет |
| Материалы не в индексе >3 недель после публикации | **Эскалация** | Порог из ТЗ, см. раздел 6 |
| Кластер не работает два периода подряд после всех правок | Закрыть кластер: новых материалов не писать, запись в `decisions.md` | Правило честного объёма — не добивать неработающее |

Решение по каждому отстающему кластеру записывается в `decisions.md` с датой. Отсутствие решения — тоже решение, но оно должно быть записано словами «рано судить, следующая контрольная точка — дата», а не подразумеваться.

## 6. Пороги эскалации в числах

Формулировки ТЗ переведены в проверяемые условия.

| Условие ТЗ | Числовой порог | Что делаю |
|---|---|---|
| «Материалы не индексируются дольше трёх недель» | Материал опубликован ≥21 день назад и отсутствует в выгрузке «Страницы в поиске» Яндекса | Останавливаюсь, запрашиваю решение. Отдельно проверяю: отправлен ли sitemap, нет ли технического дефекта |
| «Конверсия страницы встречи ниже ожидаемого диапазона два контрольных периода подряд» | `cta_vstrecha` / визиты `/vstrecha` < **3%** на КТ-N и КТ-N+1, при ≥50 визитах в каждом периоде | Останавливаюсь, запрашиваю пересмотр страницы или воронки |
| «Данные противоречат плану» | Кластер в состоянии «не работает» после двух циклов правок; либо реальная частотность из Wordstat отличается от гипотезы более чем на порядок для ≥5 кластеров | Останавливаюсь, предлагаю пересмотр стратегии, а не отдельной задачи |

Порог в 50 визитов обязателен: при меньших числах процент конверсии — статистический шум, и останавливать программу по нему было бы ошибкой.

## 7. Инструмент

`scripts/seo-report.py` читает выгрузки из `seo/data/` и сводит их в таблицу по кластерам, привязывая URL через `content/clusters.json`.

```
python3 scripts/seo-report.py
```

Проверено в двух режимах:
- **Данных нет** — печатает «выгрузок нет», указывает ожидаемый каталог и завершается кодом 0. Пустой честный вывод правильнее выдуманных цифр.
- **Данные есть** — на тестовом наборе из CSV Вебмастера и TSV Метрики свёл 11 строк в 5 кластеров, посчитал CTR и среднюю позицию, отдельно перечислил 10 кластеров без данных и URL вне кластеров.

Формат входных файлов, распознаваемые заголовки и правила именования — [data/README.md](data/README.md). Сырые выгрузки в репозиторий не коммитятся.

Если данных за период нет — сводка всё равно публикуется, с явной фиксацией: чего нет, почему, и когда ожидаются. Отчёт о несделанном замере хуже его отсутствия.
